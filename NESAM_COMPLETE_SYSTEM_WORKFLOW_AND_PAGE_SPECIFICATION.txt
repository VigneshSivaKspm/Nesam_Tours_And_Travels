 1. SYSTEM OVERVIEW & ARCHITECTURE PRINCIPLES
================================================================================

NESAM Tours & Travels is a high-reliability, real-time transportation and mobility
orchestration platform designed for outstation cabs, one-way drops, airport
transfers, local rentals, and multi-day tour packages across South India (centered
in Tamil Nadu, Kerala, Karnataka, and Andhra Pradesh).

The platform coordinates four primary operational roles in real time:
  1. Customers (Passengers): Book on-demand or scheduled trips, track drivers live,
     verify boarding using cryptographically generated 4-digit OTPs, and access
     safety/SOS features.
  2. Driver Partners: Independent owner-operators who pass 6-stage KYC verification,
     perform pre-trip vehicle safety checklists, claim marketplace rides, execute
     point-to-point journeys, and receive daily automated earnings payouts.
  3. Fleet Vendors: Travel agencies and multi-car fleet owners who register multiple
     vehicles, recruit/invite drivers under their umbrella, bid on high-value
     marketplace routes, and dispatch drivers & cars with sub-account management.
  4. Platform Administrators: Super Admins and Operations Staff who monitor live rides
     on an active telemetry grid, audit and approve KYC/fleet documents, manually
     intervene in emergencies, configure fare matrices, manage cashflows, and triage
     customer/driver support tickets.

KEY ARCHITECTURAL PILLARS:
  - Real-Time Reactivity: Direct Firestore snapshot listeners (`onSnapshot`) power
    instant dispatch, bidding updates, and state handshakes without polling lag.
  - Zero-Trust Security Model: Enforced by server-side Firebase Security Rules. Clients
    cannot escalate privileges, alter financial fare amounts after confirmation, or
    view unauthorized PII.
  - Unified Design System: Consistent enterprise design language across all panels
    (#F5F5F5 workspace background, #E21B23 Nesam brand crimson, #111111 dark accents,
    rounded-2xl cards with #E5E5E5 micro-borders, and responsive mobile-first views).
  - Resilient Phone Authentication: Firebase Phone Auth with reCAPTCHA Enterprise
    lifecycle guards, automatic localhost IP-translation, and zero-leak token caching.

 3. DATA DICTIONARY & FIRESTORE DATABASE SCHEMA
================================================================================

The platform uses Cloud Firestore in native mode. All timestamps use serverTimestamp()
on create/update to prevent client clock manipulation.

--------------------------------------------------------------------------------
 3.1 `customers` Collection
 Document ID: Firebase Auth UID (`user.uid`)
 Fields:
   - `id` (string)                 : Customer UID
   - `name` (string)               : Full passenger name
   - `phone` (string)              : E.164 formatted mobile (e.g. `+919876543210`)
   - `email` (string, optional)    : Passenger receipt email
   - `photoUrl` (string, optional) : GCS download URL for profile avatar
   - `emergencyContact` (string)   : Alternate 10-digit mobile number for SOS
   - `language` (string)           : Preferred UI language (en, ta, etc.)
   - `status` (string)             : 'Active' | 'Suspended'
   - `wallet` (string | number)    : In-app wallet credits balance
   - `bookings` (number)           : Lifetime completed trips counter
   - `spent` (string | number)     : Lifetime GMV spent
   - `createdAt` (timestamp)       : Registration time
   - `updatedAt` (timestamp)       : Last profile update

--------------------------------------------------------------------------------
 3.2 `drivers` Collection
 Document ID: Firebase Auth UID (`user.uid`)
 Fields:
   - `id` (string)                 : Driver UID
   - `name` (string)               : Driver full name
   - `phone` (string)              : Driver verified mobile number
   - `alternatePhone` (string)     : Emergency contact phone
   - `email` (string, optional)    : Driver email
   - `status` (string)             : 'Approved' | 'Pending' | 'Rejected' | 'Suspended'
   - `docStatus` (string)          : 'Pending' | 'Submitted' | 'Approved' | 'Rejected'
   - `presence` (string)           : 'Online' | 'Offline' | 'On Trip'
   - `rating` (number)             : Aggregate driver rating (e.g. 4.85)
   - `trips` (number)              : Total completed trips
   - `earnings` (string | number)  : Aggregate driver earnings
   - `walletBalance` (number)      : Available balance for withdrawal
   - `licenseNumber` (string)      : Indian Driving License (DL) Number
   - `licenseExpiry` (string)      : Expiration date (YYYY-MM-DD)
   - `vehicle` (string)            : Assigned vehicle license plate number
   - `vehicleModel` (string)       : Vehicle make & model (e.g. "Toyota Innova Crysta")
   - `vehicleCategory` (string)    : 'Sedan' | 'SUV' | 'Innova' | 'Tempo'
   - `vendorId` (string, optional) : Parent fleet vendor ID (if fleet driver)
   - `createdAt` (timestamp)       : Registration date
   - `updatedAt` (timestamp)       : Last updated date

 Subcollection: `drivers/{uid}/kyc`
   - `aadhaarFrontUrl`, `aadhaarBackUrl`, `aadhaarNumber`
   - `panCardUrl`, `panNumber`
   - `licenseFrontUrl`, `licenseBackUrl`, `badgeNumber`
   - `bankAccountName`, `bankAccountNumber`, `bankIfsc`, `bankUpi`

--------------------------------------------------------------------------------
 3.3 `vendors` Collection
 Document ID: Firebase Auth UID (`user.uid`)
 Fields:
   - `id` (string)                 : Vendor UID
   - `companyName` (string)        : Registered business or travel agency name
   - `ownerName` (string)          : Principal partner / director name
   - `phone` (string)              : Primary verified phone
   - `email` (string)              : Official billing email
   - `city` (string)               : Operating headquarters city
   - `gstin` (string)              : 15-character Goods & Services Tax ID
   - `pan` (string)                : Company / Individual PAN
   - `status` (string)             : 'PENDING_APPROVAL' | 'APPROVED' | 'REJECTED'
   - `verified` (boolean)          : Admin verification flag
   - `fleetCount` (number)         : Registered vehicle count
   - `activeDriverCount` (number)  : Active affiliated driver count
   - `commission` (number)         : Platform commission percentage (default: 10%)
   - `walletBalance` (number)      : Available vendor balance
   - `payoutInfo` (map)            : `{ bankName, accountNumber, ifsc, upiId }`
   - `contractAgreed` (boolean)    : Terms of service digital signature
   - `createdAt` (timestamp)
   - `updatedAt` (timestamp)

--------------------------------------------------------------------------------
 3.4 `bookings` Collection
 Document ID: Booking ID (`NTT-TIMESTAMP` or Auto-ID)
 Fields:
   - `id` (string)                 : Booking ID (matches doc ID)
   - `customerId` (string)         : Ordering passenger UID
   - `customer` (string)           : Passenger display name
   - `phone` (string)              : Passenger contact phone
   - `service` (string)            : 'Airport Taxi' | 'Outstation Cab' | 'One Way Taxi' | 'Local Rental' | 'Tour Package'
   - `vehicle` (string)            : Requested category (Sedan, SUV, Innova, Tempo)
   - `pickup` (string | map)       : Pickup location address & geo coordinates
   - `drop` (string | map)         : Destination location address & geo coordinates
   - `date` (string)               : Scheduled pickup date (YYYY-MM-DD)
   - `time` (string)               : Scheduled pickup time (HH:mm)
   - `distanceKm` (number)         : Estimated route distance
   - `fare` (number)               : Gross fare in INR
   - `fareBreakdown` (map)         : `{ baseFare, distanceFare, gst, driverAllowance, tollEstimate }`
   - `status` (string)             : 'Pending' | 'Confirmed' | 'Assigned' | 'Ongoing' | 'Completed' | 'Cancelled'
   - `tripStage` (string)          : 'En Route Pickup' | 'Reached Pickup' | 'In Progress' | 'Arrived Destination'
   - `assignedDriverId` (string)   : UID of the driver executing the ride
   - `assignedDriverName` (string) : Driver display name
   - `assignedDriverPhone` (string): Driver phone number
   - `assignedVehicleNumber`(str)  : Vehicle plate number
   - `assignedVendorId` (string)   : Vendor UID (if trip awarded to fleet vendor)
   - `vendorPayout` (number)       : Net payable to vendor after commission
   - `driverEarnings` (number)     : Net payable to driver
   - `payment` (string)            : Payment status ('Pending' | 'Paid' | 'Refunded')
   - `paymentMethod` (string)      : 'UPI' | 'Cash' | 'Card' | 'Wallet'
   - `tollsAmount` (number)        : Recorded toll/parking charges added at finish
   - `source` (string)             : 'customer_app' | 'admin' | 'vendor_b2b'
   - `createdAt` (timestamp)       : Order creation timestamp
   - `startedAt` (timestamp)       : Time OTP was verified and meter started
   - `completedAt` (timestamp)     : Time trip concluded

--------------------------------------------------------------------------------
 3.5 `booking_secrets` Collection (Restricted Security Vault)
 Document ID: Booking ID (`bookings/{bookingId}`)
 Access: Cloud Functions & Server Admin only.
 Fields:
   - `bookingId` (string)          : Matching booking reference
   - `boardingOTP` (string)        : Cryptographically random 4-digit code (e.g. "4892")
   - `generatedAt` (timestamp)

--------------------------------------------------------------------------------
 3.6 `marketplace_trips` Collection
 Document ID: Matches Booking ID
 Fields:
   - `id` (string)                 : Trip ID
   - `pickup` (string | map)       : Pickup locality and city
   - `drop` (string | map)         : Drop locality and city
   - `date`, `time` (string)       : Departure schedule
   - `service`, `vehicle` (string) : Service type and vehicle required
   - `fare` (number)               : Offered gross passenger fare
   - `driverPayout` (number)       : Standard driver rate (85% of fare)
   - `status` (string)             : 'Open' | 'Bidding' | 'Assigned' | 'Closed'
   - `assignedDriverId` (string)   : Assigned driver ID
   - `assignedVendorId` (string)   : Assigned vendor ID
   - `createdAt` (timestamp)

 Subcollection: `marketplace_trips/{tripId}/bids`
 Document ID: Auto-ID or `BID-TIMESTAMP`
 Fields:
   - `id` (string)                 : Bid ID
   - `tripId` (string)             : Reference trip
   - `vendorId` (string)           : Bidding vendor UID
   - `vendorName` (string)         : Vendor business name
   - `vendorCounterRate` (number)  : Counter-offered fare
   - `offeredPayout` (number)      : Net payout expected
   - `biddingNote` (string)        : Vehicle details / driver assignment note
   - `status` (string)             : 'Pending Review' | 'Accepted' | 'Declined'
   - `submittedAt` (timestamp)

--------------------------------------------------------------------------------

 Document ID: Auto-ID or `VEH-TIMESTAMP`
 Fields:
   - `id` (string)                 : Vehicle record ID
   - `plateNumber` (string)        : Vehicle registration (e.g. "TN 01 AB 1234")
   - `category` (string)           : 'Sedan' | 'SUV' | 'Innova' | 'Tempo Traveller'
   - `make` (string)               : e.g. "Maruti Suzuki", "Toyota", "Force"

 10. SECURITY ARCHITECTURE (RBAC, FIRESTORE RULES & AUDIT SAFEGUARDS)
================================================================================

 10.1 Role-Based Access Control (RBAC):
   - Customer: Can only read/write their own profile in `customers/{uid}` and orders
     where `customerId == auth.uid`. Cannot alter fares or assign drivers.
   - Driver: Can read assigned trips, write trip telemetry and stage updates, but
     cannot alter gross fare or delete bookings.
   - Vendor: Can manage their own vehicles (`vehicles`), invite drivers (`driver_invites`),
     submit bids in `marketplace_trips/{id}/bids`, and dispatch assigned trips.
   - Super Admin: Full read/write authority guarded by `admins/{uid}` record and
     Firebase custom claims.

 10.2 Cryptographic Boarding Vault (`booking_secrets`):
   - Boarding OTPs are isolated in a separate `booking_secrets` collection.
   - Neither drivers nor vendors can read this collection.
   - OTP validation is performed server-side or via secured document reference,
     preventing driver client impersonation.

 10.3 API & Financial Secret Isolation:
   - Zero API secret keys in client-side code or Firestore documents.
   - Razorpay secret keys, webhook secrets, and SMS gateway credentials are
     configured exclusively in serverless Cloud Functions environment secrets.

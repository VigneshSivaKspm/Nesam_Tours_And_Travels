 4. SECURITY FINDINGS
================================================================================
 S1 [BLOCKER] Admin UI email backdoor still present
    admin/src/App.tsx:330-335 and admin/src/services/authService.ts:37-42 treat
    any email containing "admin" or ending "@nesam.in" as Super Admin. Rules
    no longer honour this (tested), so the hole is closed at data level, but
    the UI must be fixed: such users land in a shell where every list is
    empty and every save fails. Remove both blocks; rely on admins/{uid}.role.

 S2 [BLOCKER] Payment gateway secret readable by all users
    Settings.tsx:29-30 saves rzpKey / rzpSecret into settings/config.
    firestore.rules: settings → read: isSignedIn(). Any customer/driver/vendor
    can read the secret. Never store a secret in Firestore for a client-only
    app. Remove the field; keep secrets only in a server (Cloud Function)
    when payments are introduced. Split public settings (company name, GST
    rate, cancel window) from admin-only settings.

 S3 [BLOCKER] Customer-controlled fare
    Rule accepts any numeric fare >= 0. A customer can book at ₹0 or ₹1.
    Without a server, mitigate: (a) admin must "confirm fare" before the
    booking is published (booking status Pending → admin-verified), or (b)
    enforce minimum fare per category in rules (read vehicle_categories),
    or (c) move booking creation to a Cloud Function (recommended).

 S4 [CRITICAL] Payout amount not bounded
    payout_requests create only checks amount > 0. A driver/vendor can
    request any amount. Admin must verify against the ledger before paying
    (add the computed available balance next to each request in admin UI).

 S5 [CRITICAL] Marketplace readable by unapproved partners
    marketplace_trips read: isVendor() || isDriver() — includes Pending /
    Rejected / Suspended accounts. Customer pickup/drop addresses leak to
    unvetted accounts. Use isApprovedVendor() || isApprovedDriver().

 S6 [MAJOR] Vendor-linked drivers can self-claim marketplace trips
    driverClaimOk does not require vendorId == ''. A fleet driver can take
    trips independently of their vendor. Decide the business rule; enforce.

 S7 [MAJOR] No vehicle-category check on claims
    A Sedan driver can accept a Tempo Traveller booking.

 S8 [MAJOR] Storage: customers/ path missing
    user/web storageService.ts:41 uploads avatars to customers/{uid}/… — no
    matching storage rule → every customer photo upload is denied.

 S9 [MAJOR] driver_presence collection missing from rules
    Customer rideService.ts:52 reads `driver_presence` (nearby drivers map).
    No rule → default deny; nothing writes it either (driver app writes
    drivers/{uid}.presenceStatus). Either add the collection (driver writes
    own doc, approved customers read) or drop the feature.

 S10 [MAJOR] b2b_partners removed from rules — the B2B page has no backing
     collection permission (page is also unreachable — §5.24).

 S11 [MINOR] Admin self-signup creates admins/{uid} as 'pending' with no
     admin UI to approve pending admins (must be done in Firebase console).

 S12 [MINOR] Staff & Roles records do not grant or restrict anything — every
     approved admin has full access; "permissions" are cosmetic.

 S13 [IMPROVE] Enable Firebase App Check before launch (currently opt-in via
     VITE_APPCHECK_ENABLED); restrict API key by HTTP referrer in GCP console.

            Marketplace, Add Driver (old), Register Vendor, Register Vehicle,

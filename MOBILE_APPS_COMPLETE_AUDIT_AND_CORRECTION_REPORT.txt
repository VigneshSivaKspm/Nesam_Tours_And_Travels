 13. FIRESTORE SCHEMA INCONSISTENCIES
--------------------------------------------------------------------------------
   * Booking status vocabulary: Pending → Confirmed → Assigned → Ongoing →
     Completed | Cancelled; tripStage: Assigned → En Route Pickup → Reached
     Pickup → In Progress → Arrived Destination → Completed. Prototype apps use
     'Driver Assigned', 'Trip Started' (Customer) — not platform values.
     functions/otp.ts writes 'Trip Started' (BKD-06).
   * Admin bid award sets status 'Assigned' with no driver; the customer view
     must treat "Assigned without assignedDriverId" as partner-confirmed.
   * Vendor status: canonical INCOMPLETE / PENDING_APPROVAL / CHANGES_REQUESTED
     / APPROVED / REJECTED / SUSPENDED (legacy spellings still honoured by rules).
   * Bid status 'Pending Review' (rules L474); Admin UI checks 'Pending' /
     'Counter' → awards buttons never show for mobile/web vendor bids.
   * Payout statuses: Pending → Paid | Deferred | Rejected (admin DriverEarnings).
     No UTR field is written by Admin; apps can only display one if added.

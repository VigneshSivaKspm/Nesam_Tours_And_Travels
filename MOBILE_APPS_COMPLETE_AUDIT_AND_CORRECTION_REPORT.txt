     booking with live fare engine / coupons / scheduling / saved places, live

     expiry tracking, driver roster / vehicle assignment / invites, wallet with

 3. TECHNOLOGY STACK (all three apps)
--------------------------------------------------------------------------------

   Expo SDK 57 (expo 57.0.25), React Native 0.86.3, React 19.2.3, TypeScript
   6.0 strict. New Architecture (default). Hermes.
   Android: compileSdk 36, targetSdk 36 (current Play requirement), minSdk 24,
   AGP 8.12, Gradle 9.3.1, NDK 27.1, R8 minify + resource shrinking in release.
   Firebase JS SDK 12.19 (auth with getReactNativePersistence(AsyncStorage),
   Firestore memory cache + long-polling auto-detect, Storage).
   Navigation: React Navigation 7 (native-stack + bottom-tabs).
   Location: expo-location (Customer, Driver). Maps: react-native-maps, only
   when a Google Maps key is supplied (Customer). Camera/gallery:
   expo-image-picker + expo-image-manipulator. Documents: expo-document-picker
   (Vendor). Dates: @react-native-community/datetimepicker. Network: NetInfo.
   Receipts: expo-print + expo-sharing (Customer). Keep-awake during trips
   (Driver). State: React context per signed-in session.
   Why SDK 57 (upgrade from 52): SDK 52 targets API 34, below Google Play's
   target-API requirement; SDK 57 also matches the Web apps' React 19.

   Phone authentication: Firebase JS SDK phone auth (RN build) with an
   app-local reCAPTCHA v2 verifier (components/RecaptchaVerifier.tsx) hosted
   on the project's authorised authDomain — same technique as the deprecated
   expo-firebase-recaptcha. Verified live: the project's reCAPTCHA Enterprise
   enforcement for PHONE_PROVIDER is UNSPECIFIED, so the v2 path applies. The
   WebView is only the verification challenge; every app screen is native.
   Alternative for later: @react-native-firebase/auth (needs google-services.json).
